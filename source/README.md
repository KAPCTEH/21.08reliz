# Исходный код JustFun «Заказы и логистика» 7.8.3

Архив исходников состоит из четырёх обязательных частей:

- `application` — Electron-приложение, интерфейс, локальное защищённое
  хранение, синхронизация, Telegram и исходник сервиса данных REG.RU;
- `installer` — нативные Windows Setup, Recovery и штатное удаление;
- `license-server` — центральные учётные записи, компании, роли, устройства,
  одноразовые приглашения и маршруты авторизации сервиса данных.
- `desktop-runtime` — сценарий воспроизводимой сборки Windows-payload на
  зафиксированной версии Electron.

## Основная схема работы

Установщик один для всех компьютеров. После установки пользователь входит в
свою учётную запись. Сервер возвращает компанию, роль, разрешения, список
доступных складов и адрес общего сервиса данных. Данные на одном компьютере
дополнительно разделены по идентификатору компании, поэтому вход в другую
компанию не открывает локальный кэш предыдущей.

## Сборка

Для сборки нужны Node.js 24, Python 3.12, NSIS 3.x и зависимости из
`desktop-runtime/package.json` и `installer/package.json`.

Сначала собирается чистый Windows-payload:

```text
python desktop-runtime/build_payload.py \
  --app-dir application \
  --electron-dist desktop-runtime/node_modules/electron/dist \
  --output-dir build/payload
```

Затем создаётся установщик:

```text
python installer/build_windows.py \
  --payload-dir build/payload \
  --logo ПУТЬ_К_ОФИЦИАЛЬНОМУ_ЛОГОТИПУ \
  --output-dir ПУТЬ_К_РЕЗУЛЬТАТУ \
  --node-modules ПУТЬ_К_NODE_MODULES \
  --makensis ПУТЬ_К_MAKENSIS.EXE
```

Скрипт проверяет версию payload и точные SHA-256 исходного и прозрачного логотипов,
собирает нативные Setup и Recovery, встраивает штатный Uninstall, проверяет
структуру PE-файлов и отсутствие старых сценарных зависимостей.

## Серверы

Сначала публикуется `license-server` и применяются его схема и миграции.
Затем владелец компании один раз запускает мастер REG.RU в программе.
Параметры общего сервера сохраняются в профиле компании, поэтому на остальных
компьютерах достаточно установить тот же дистрибутив и войти в свой аккаунт.
Изменения активного склада отправляются автоматически; новые серверные ревизии
периодически загружаются на остальные компьютеры. Конфликтующая запись
блокируется до явного выбора актуальной версии и не перезаписывает чужие данные.

Рабочие секреты, пароли и локальные конфигурации в исходный архив не входят.


## Исправление контекста владельца REG.RU

Сессия пользователя теперь восстанавливает идентификаторы пользователя и компании из подписанных сервером JWT-полей `sub` и `cid`, проверяет отсутствие противоречий с JSON-ответом и перед настройкой VPS заново подтверждает роль, компанию и компьютер через `/v1/auth/introspect`. Локальная конфигурация REG.RU больше не используется, если её `workspace_id` не совпадает с подтверждённой компанией. Telegram-подключение хранится в отдельном зашифрованном корпоративном сервисе `company-telegram-broker`: он проверяет каждую действующую сессию через опубликованный `license-server`, но не меняет его код, D1-базу или секреты. Сотрудники обращаются к боту только для складов, перечисленных в серверных правах `jf.warehouse:<id>`. Рабочий `license-server` должен сообщать `auth_contract: 4`, а отдельный broker — `broker_contract: 1`.
