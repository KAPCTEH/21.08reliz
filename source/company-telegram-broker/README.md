# Корпоративный Telegram-broker JustFun

Этот Worker хранит отдельное Telegram-подключение для каждой пары
`компания + склад` и не изменяет рабочий сервер авторизации. Одна D1-база
broker обслуживает все такие записи; новая база на каждый склад не создаётся.
Каждый запрос сотрудника подтверждается через
`/v1/auth/introspect` действующего `justfun-license-api`. Для связи между
двумя Worker используется Cloudflare Service Binding `AUTH_SERVICE`; внешний
HTTPS-адрес остаётся только совместимым резервным транспортом.

Секретный ключ Telegram Worker:

- шифруется AES-GCM с отдельным секретом `INTEGRATION_SECRET`;
- хранится только в отдельной D1-базе broker;
- никогда не возвращается в настольное приложение;
- используется только для разрешённых маршрутов Telegram API.

Доступ к складу проверяется по серверному праву `jf.warehouse:<warehouse_id>`.
Владелец, `*` и `jf.warehouse:*` имеют доступ ко всем складам.

## Развёртывание

1. Один раз создать общую D1-базу broker `justfun-company-telegram`.
2. Для действующей инфраструктуры использовать проверяемый `wrangler.jsonc`.
   Для другой Cloudflare-учётной записи скопировать
   `wrangler.jsonc.example`, указать ID её базы и проверить привязку
   `AUTH_SERVICE` к Worker `justfun-license-api`. `wrangler.toml.example`
   оставлен только для совместимости.
3. Для новой базы выполнить `schema.sql`. Для существующей базы с одной
   конфигурацией на компанию выполнить `migrations/0002-warehouse-services.sql`.
   Старая запись `warehouse_id='*'` сохраняется только для ручного разбора и
   больше не участвует в отправке. Владелец должен явно переподключить бота
   каждому складу; неоднозначное старое подключение автоматически не назначается.
4. Установить отдельный случайный `INTEGRATION_SECRET` длиной не менее 32 знаков.
5. Опубликовать Worker и проверить `/health`, `broker_contract: 1`.

Флаг `global_fetch_strictly_public` обязателен: broker проверяет отдельный
Telegram Worker компании по его публичному адресу `*.workers.dev`. Без этого
флага Cloudflare блокирует вызов Worker → Worker ошибкой 1042, проверка
завершается до `UPSERT`, а таблица `company_telegram_services` остаётся пустой.

Наблюдаемость включена в примерах конфигурации. Журнал содержит только код,
HTTP-статус, тип ответа и `cf-ray`; токен бота и клиентский ключ не записываются.

Рабочий `justfun-license-api`, его D1-база и секреты при этом не меняются.
