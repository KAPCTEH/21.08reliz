## Уточнение владельца от 2026-08-23

Полная база ГАР/ФИАС не загружается, не распаковывается и не включается в проект. Адреса ищутся по запросу через внешний сервис. На стороне JustFun разрешён только ограниченный временный кэш сетевых ответов; в заказе сохраняется выбранный пользователем адрес и его служебные идентификаторы.

Причина изменения: владелец прямо потребовал «не добавлять их, просто научиться находить». Это требование заменяет прежний план собственного многогигабайтного индекса.

## Целевая цепочка

```text
поле адреса
  → debounce + cancellation + request_id
  → scoped VPS address-search API
  → нормализация и разбор русского адреса
  → настроенный внешний поставщик подсказок с ФИАС-кодами и координатами
  → при отсутствии ключа: только явный поиск по кнопке через Nominatim
  → объединение и дедупликация
  → regional bias текущего склада
  → confidence/ranking
  → до 3 достоверных вариантов
  → подтверждение пользователя
  → canonical address + original input + coordinates + source IDs
```

## Реализованная архитектура

1. Desktop передаёт запрос только в scoped endpoint своей компании, склада и среды.
2. VPS использует DaData Suggestions API, если в защищённой переменной окружения задан `JF_DADATA_API_KEY`.
3. [DaData Suggestions](https://dadata.ru/api/suggest/address/) выбрана как подключаемый поставщик: она возвращает ФИАС-код, части российского адреса и доступные координаты, умеет исправлять опечатки и поддерживает земельные участки.
4. Без ключа автоматические подсказки запрещены. Явное нажатие кнопки может выполнить один пользовательский запрос через Nominatim.
5. Публичный Nominatim не используется для автодополнения: это прямо запрещено [правилами его публичного сервера](https://operations.osmfoundation.org/policies/nominatim/).
6. Ответы хранятся только во временном ограниченном кэше памяти процесса; адресная база и архивы в проект не добавляются.
7. В заказ сохраняются исходный ввод, нормализованный ввод, выбранный адрес, координаты, точность, ФИАС-код и идентификаторы поставщика.

Нельзя объявлять блокер закрытым после одного демонстрационного запроса. Требуются метрики и живые проверки всех приоритетных регионов.

## Реализовано в исходном коде

- отдельный браузерный и Node-совместимый модуль нормализации/ранжирования;
- сокращения для области, района, города, деревни, села, посёлка, СНТ, ДНТ, ДНП, массива, улицы, дома, корпуса, строения и участка;
- нечёткое сопоставление слов через расстояние Дамерау—Левенштейна;
- учёт номера дома/участка и явно указанного региона;
- мягкий приоритет Санкт-Петербурга, Ленинградской, Новгородской, Псковской, Московской областей, Карелии и Москвы;
- дедупликация и выдача максимум трёх вариантов;
- понятная оценка совпадения и предупреждение, если адрес требует проверки;
- автоподсказка через 700 мс и отмена устаревшего сетевого запроса;
- автоматический тест и обязательный запуск теста в Windows release gate.
- версионированный серверный контракт `address_search=1`;
- защищённый adapter DaData: ключ передаётся только в HTTP-заголовке с VPS и не попадает в renderer или журналы;
- сохранение ключа при повторном развёртывании VPS;
- явный режим `autocomplete` / `explicit` и запрет public-Nominatim fallback для автоподсказок;
- временный кэш и ограничение частоты запросов;
- mock-интеграционные тесты DaData, Nominatim, Top-3, дедупликации, ФИАС-кода и координат;
- строгая проверка внешнего ответа: неверные даты, координаты, рейтинги, поля и ФИАС-коды отклоняются;
- договор адресного поиска включён в совместимость подписанных обновлений.

## Что остаётся обязательным до закрытия блокера

- владелец создаёт учётную запись поставщика и лично вводит `JF_DADATA_API_KEY` на VPS;
- production VPS подтверждает `address_provider=dadata` и `address_autocomplete=true` без раскрытия ключа;
- выполняются живые запросы с ошибками, сокращениями, СНТ/ДНТ/ДНП, массивами, деревнями, сёлами, домами и участками по семи приоритетным регионам;
- создаётся эталонный корпус минимум 2 000 адресов / 10 000 вариантов ввода и измеряются Top-1, Top-3 и p95;
- подтверждается поведение при исчерпании лимита, отказе поставщика, отсутствии координат и ручной точке на карте;
- выполняется визуальная и установленная Windows-приёмка.

Исходные тесты не доказывают качество живого поставщика. До ввода реального ключа и прохождения корпуса `JF3-BLOCKER-002` остаётся `OPEN`.
