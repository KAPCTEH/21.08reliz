## Подтверждённая текущая цепочка

```text
deliveryAddress + кнопка
  → searchDeliveryAddress
  → geocodeSearch / expandAddressQuery / rankGeocodeResults
  → desktop:maps-geocode
  → directOpenStreetMapGeocode
  → public Nominatim
  → при отказе: REG VPS /v1/maps/geocode
  → proxy_geocode
  → Nominatim
  → выбор результата
  → order.geo + расчёт OSRM
```

## Текущие возможности

- поиск и reverse geocode;
- российский country filter;
- северо-западный viewbox как мягкий приоритет;
- отмена устаревшего запроса;
- кэш;
- несколько простых сокращений;
- ручная точка на карте;
- fallback через VPS;
- request ID и безопасная диагностика состава адреса.

## Целевая цепочка

```text
поле адреса
  → debounce + cancellation + request_id
  → server address-search API
  → нормализация и разбор русского адреса
  → локальный индекс ГАР/ФИАС + fuzzy index
  → разрешённый картографический источник координат
  → объединение и дедупликация
  → regional bias текущего склада
  → confidence/ranking
  → до 3 достоверных вариантов
  → подтверждение пользователя
  → canonical address + original input + coordinates + source IDs
```

## Первый технический инкремент

1. Зафиксировать server/API contract и result schema.
2. Вынести нормализацию и ранжирование в отдельный тестируемый модуль.
3. Ограничить UI тремя результатами и добавить confidence/warning без молчаливого выбора.
4. Добавить словарь типов и сокращений для малых населённых пунктов и территорий.
5. Создать небольшой контрактный seed приоритетных регионов для TDD.
6. Затем подключать версионированный ГАР/ФИАС и масштабировать корпус до обязательного размера.

Нельзя объявлять блокер закрытым после одного демонстрационного запроса. Требуются метрики и живые проверки всех приоритетных регионов.

## Реализовано в первом инкременте

- отдельный браузерный и Node-совместимый модуль нормализации/ранжирования;
- сокращения для области, района, города, деревни, села, посёлка, СНТ, ДНТ, ДНП, массива, улицы, дома, корпуса, строения и участка;
- нечёткое сопоставление слов через расстояние Дамерау—Левенштейна;
- учёт номера дома/участка и явно указанного региона;
- мягкий приоритет Санкт-Петербурга, Ленинградской, Новгородской, Псковской, Московской областей, Карелии и Москвы;
- дедупликация и выдача максимум трёх вариантов;
- понятная оценка совпадения и предупреждение, если адрес требует проверки;
- автоподсказка через 700 мс и отмена устаревшего сетевого запроса;
- автоматический тест и обязательный запуск теста в Windows release gate.

## Что остаётся обязательным

- серверный индекс ГАР/ФИАС и его версионирование;
- нечёткий поиск по базе до обращения к геокодеру, чтобы исправлять ошибку даже тогда, когда Nominatim не вернул правильный объект;
- устойчивый внутренний ID, объединение результатов разных разрешённых источников и правила свежести;
- эталонный корпус, измеримые Top-1/Top-3/p95 и живые проверки;
- контролируемая production-инфраструктура вместо зависимости от публичного Nominatim.
