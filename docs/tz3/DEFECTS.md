Подтверждённые факты:

- `source/application/update/policy.json`: `enabled=false`;

- allowlist хостов пуст;

3. Staging endpoint и allowlist настроены.
4. Подписанный каталог и пакет проходят обновление и откат.
5. Stable включается только после canary.

### JF3-BLOCKER-002 — Поиск адресов не соответствует обязательному Stage 39

| Поле | Значение |
|---|---|
| Тип | Release blocker |
| Приоритет | P1 до финального выпуска |
| Обнаружено | JF3-S0012 |
| Коммит | `b3a9e7c0f2892b4e3276b51ca5c0ee1760e88568` |
| Состояние | OPEN |
| GitHub | https://github.com/KAPCTEH/21.08reliz/issues/24 |

Подтверждённое baseline-поведение:

- поиск запускается отдельной кнопкой;
- renderer запрашивает до 10 результатов Nominatim;
- основной и VPS fallback используют один класс данных Nominatim/OpenStreetMap;
- нормализация заменяет только несколько сокращений;
- ранжирование основано на простом вхождении слов и номера дома;
- отдельного ГАР/ФИАС-слоя и локального нечёткого индекса нет;
- confidence, контракт «до трёх достоверных вариантов», эталонный корпус и benchmark отсутствуют.

Частично исправлено коммитами `4ba860a25cceb2cef4a43c85ea25a0fc9cd030b3` и `ad4136d`:

- появились автоподсказки, расширенная нормализация, нечёткое ранжирование, предупреждения и Top-3;
- добавлены дедупликация, региональный приоритет и проверка номера дома/участка;
- добавлен изолированный тест и его обязательный запуск в Windows release gate;
- по прямому уточнению владельца полный ГАР/ФИАС-индекс отменён;
- добавлен scoped VPS-контракт поиска, adapter внешнего поставщика с ФИАС-кодами и координатами, временный кэш и безопасное хранение ключа;
- public Nominatim не используется для автоподсказок; без ключа доступен только явный поиск по кнопке;
- повреждённые ответы внешнего поставщика, неверные координаты и неверные ФИАС-коды отклоняются;
- блокер не закрыт: реальный ключ поставщика не введён, production и большой корпус не проверены.

Условие закрытия:

1. Утверждена и реализована серверная архитектура поиска без локальной базы.
2. Подключён реальный разрешённый поставщик с ФИАС-кодами и координатами.
3. Реализованы нормализация, опечатки, сокращения, дедупликация и Top-3.
4. Созданы автоматические отрицательные и контрактные тесты.
5. Создан эталон минимум 2 000 адресов / 10 000 запросов.
6. Выполнены метрики и живые проверки приоритетных регионов.
